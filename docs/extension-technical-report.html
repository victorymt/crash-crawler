1. 背景与目标

Provider Usage Hub 用于聚合多家 AI Provider 的余额、用量、订阅与代金券信息。 仓库同时提供 Python/Web 看板与 Chrome/Edge Manifest V3 扩展。 扩展版不依赖 server.py 与 BrowserOS profile 同步，直接复用当前浏览器登录态。

核心问题
采集成本
SPA 页面依赖 JS 渲染时，后台开 Tab 慢、重、易抖
优化方向
API First
能 JSON 则 fetch；失败再回退 DOM / Tab

产品能力摘要

  • Popup 看板：并行刷新、单源刷新、打开官方页、复制 URL
  • Options：内置源可改 URL/名称；自定义「书源」式 CSS 选择器规则
  • 后台 chrome.alarms 定时刷新 + 工具栏角标
  • 内置：OpenCode、DeepSeek（官方 API）、EZAICLUB（API 优先）、SiliconFlow（页面）

模块职责

路径 职责
background/service_worker.js 消息路由、并发刷新池、alarm、角标、配置读写
providers/index.js 各 provider 采集编排：API / HTTP / Tab / Selector
shared/parsers.js HTML token、JSON API、通用书源规则解析
shared/storage.js 配置合并、快照写锁、密钥与自动刷新设置
popup / options 展示与书源编辑；popup 监听 storage.onChanged
设计原则：Service Worker 只做编排；解析逻辑尽量纯函数并放在 parsers.js，便于 Node 单测与 Python 侧对照。

3. 采集策略分层

「必须开 Tab」并非架构铁律，而是数据可达性决定的兜底手段。

1
官方 / 内部 JSON API DeepSeek Bearer Key；EZAICLUB Bearer + localStorage.auth_token
2
复用已打开标签 tabs.query + executeScript 读 DOM 或 storage，不新建 Tab
3
credentials 的 HTTP fetch(url, { credentials: "include" }) 拉 HTML（SSR 场景）
4
后台 Tab 渲染 SPA 无有效静态字段时 tabs.create({ active: false }) 等待就绪再抽文本
Provider 主路径 是否常开 Tab
DeepSeek api.deepseek.com/user/balance 否
EZAICLUB API first，DOM fallback 有 token 时否；否则短时开 Tab 读 token 或回退 DOM
OpenCode HTTP / 页面 token 解析 视页面是否 SSR
SiliconFlow API first（wallets + profile），DOM fallback 有 subject id 时否；否则短时开 Tab 读 id 或回退 DOM
自定义 page CSS 选择器 / 正则规则 通常是

4. 逆向方法论（实操）

目标：找出页面数字背后的 XHR/Fetch，在扩展 background 中用同一登录态复现。 本轮对 EZAICLUB / SiliconFlow 使用 BrowserOS（已登录会话）完成； chrome-devtools MCP 因本机缺少 Google Chrome stable 可执行文件未直接使用。

4.1 标准步骤

  1. 登录后打开余额 / 订阅 / 券页面
  2. DevTools → Network → 过滤 Fetch/XHR，Preserve log
  3. 刷新或切换 Tab，搜索 balance / subscription / wallet
  4. 记录 Method、URL、鉴权头、响应 JSON 路径
  5. 在页面 Console 用 fetch 复现；扩展侧再落代码

4.2 EZAICLUB 结论

项 内容
鉴权 Authorization: Bearer <JWT>，JWT 存于 localStorage.auth_token
仅 Cookie 返回 401 Authorization header is required
余额 GET /api/v1/auth/me?timezone=Asia/Shanghai → data.balance
订阅 GET /api/v1/subscriptions/active?timezone=… → 套餐名、到期、日/周/月用量

4.3 SiliconFlow 结论（已接入 API first）

项 内容
鉴权 Cookie 会话 + 请求头 x-subject-id
Subject window.SF_SUBJECT_ID / subjectInfo.subjectId
钱包 / 券 /walletd-server/api/v1/subject/wallets?stage=1|3 + profile/peek
金额单位 大整数 ÷ 1e12 为元；小数视为已是元
实现 collectSiliconflowViaApi → 失败回退 DOM；raw.source 为 api|page
安全注意：报告与日志中不得粘贴完整 JWT / refresh_token。 扩展 background 无法直接读页面 localStorage，需通过 scripting.executeScript 在目标 origin 上下文中读取。

5. EZAICLUB API 落地设计

5.1 控制流

collectEzaiclub(config)
  ├─ collectEzaiclubViaApi(config)
  │    ├─ getEzaiclubAuthToken()
  │    │    ├─ 已打开 ezaiclub tab → localStorage.auth_token
  │    │    └─ 否则短时 create 后台 tab，轮询 token 后关闭
  │    ├─ fetch /api/v1/auth/me
  │    ├─ fetch /api/v1/subscriptions/active
  │    └─ ezaiclubApiSnapshot()  → raw.source = "api"
  └─ 失败 / 无 token / 空结果
       └─ collectEzaiclubViaPage()  → 原 DOM 双页采集，raw.source = "page"

5.2 解析映射

API 字段 看板字段
data.balance 余额 metric（USD，两位小数）
data.frozen_balance（>0） 冻结余额
group.name 当前套餐
status / expires_at 订阅状态 / 到期时间
*_usage_usd / *_limit_usd 用量条（percent + $used / $limit）

5.3 关键实现文件

  • extension/src/providers/index.js — token 读取、API fetch、回退编排
  • extension/src/shared/parsers.js — parseEzaiclubAuthMe、parseEzaiclubSubscriptionsApi、 ezaiclubApiSnapshot
  • tests/ezaiclub-api.test.mjs — 解析与「有 token 时不新开 Tab」契约
收益：已登录且存在同站 Tab 时，刷新接近纯网络请求； 后台定时刷新可显著减少长时间后台 Tab 占用。DOM 路径仍保留，兼容未登录或接口变更。

6. 工程优化清单（0.2 → 0.4）

项 说明
内置 URL 可配置 锁定 id/type/mode；允许改 name、targetUrl、secondaryUrls、enabled（OpenCode workspace）
refreshAll 批写 一次读配置/快照，API 全并行、页面限并发，一次性 saveSnapshots
渲染等待收敛 轮询 250ms；selector 就绪即停；上限约 12–16s
图标与角标 异常 / 建议充值 / 关注数量展示在 toolbar badge
storage 驱动 UI popup 监听快照变更，后台写完自动刷新卡片
定时刷新 alarms + 设置页间隔；默认只复用已打开页面，不静默创建后台 Tab
快照写锁 并行 saveSnapshot 不丢更新
可恢复刷新任务 网络/页面步骤独立限流，单来源完成即落盘；storage.session 保存进度并清理遗留 Tab
访问时更新 内置来源默认监听页面访问；自定义来源显式选择，content script 不读取或上传任意存储内容
采集诊断 raw.collection 记录策略、耗时、错误码与 fallback，敏感字段统一脱敏

8. 测试与验证

扩展侧使用 Node 内置 test runner：

npm test
# node --test tests/*.test.mjs
  • Parser 单测：余额 / 订阅 token、API JSON 映射
  • Provider 集成：API 成功路径不 tabs.create；无 token 时回退 DOM
  • Background：并发 refreshAll、单次 snapshot 批写、alarm 设置
  • Storage：内置 URL 保留、快照写锁、设置归一化
手工验收建议：扩展重新加载 → 保持 EZAICLUB 已登录 → 刷新单卡 → 检查 popup 数据与 raw.source === "api"（可在测试预览或调试日志中观察）。

9. 风险与后续工作

风险

  • 无文档 API：路径或字段变更会导致 API 路径失败（已有 DOM 回退）
  • Token 生命周期：JWT 过期后需用户重新打开站点或走 refresh（当前未实现 refresh_token 刷新）
  • 站点 ToS：自动化采集仅建议个人自用聚合
  • Alarm 精度：Chrome 休眠时可能推迟触发

建议后续

  1. SiliconFlow：接入 x-subject-id + wallets API（已完成）
  2. EZAICLUB：可选实现 refresh_token 静默续期，减少短开 Tab
  3. OpenCode：Network 逆向是否可无渲染
  4. 修复 chrome-devtools MCP 的 Chromium 路径，便于日后纯 DevTools 抓包

D. 一句话总结

Provider Usage Hub 扩展以「统一 snapshot + 可插拔采集」为核心； 页面 Tab 是通用兜底，JSON API 是性能与稳定性的主航道。 EZAICLUB 已完成从 DOM 刮取到 API 优先的第一跳，为其余 SPA 源提供了可复制模板。
